# C0015 Lab Payloads — Benign, Config-Driven, Runnable

All payloads in this directory are benign surrogates. Every lab value (URL, host, path, corpus) is read from
`payloads/config/c0015.example.ini` (the template) or from the per-run manifest generated by the harness — no
lab values are hardcoded in code. There is no malware, no injection, no credential extraction, and no real
encryption.

> Full attack runbook (entry -> beacon -> discovery -> WMI -> impact, machine by machine):
> **`docs/attack-runbook.md`** (scripts in `payloads/packaging/`).

## Build & Run (Only on Your Lab Machines, After Approval)

```powershell
# 1. Build the DLL (on Kali or a host with mingw) — the output is named .jpg (T1036)
x86_64-w64-mingw32-gcc -shared -o c0015-comparefor.jpg payloads/dll/c0015_bootstrap_dll.c -lshlwapi

# 2. Config: copy the example, fill in per-run values (do not put secrets in this file)
copy payloads\config\c0015.example.ini C:\Users\Public\C0015\config.ini   # on WS01
#    Also place the HTA, the DLL (c0015-comparefor.jpg), and the beacon in C:\Users\Public\C0015\

# 3. Macro: paste the contents of macro_payload.vba into the module of a test.docm (Document_Open)

# 4. Offline beacon test (same lab host):
python scripts\c2sim_v2.py --ip 127.0.0.1 --port 8080 --ledger evidence\run-ledger --log c2sim.log
powershell -NoProfile -ExecutionPolicy Bypass -File payloads\beacon\c0015_beacon.ps1 -Config <test.ini> -Once

# 5. Impact cycle (dummy corpus in a temporary directory, manifest generated by the harness):
.\payloads\impact\c0015_impact.ps1 -Manifest <impact-manifest.json> -Action Prepare
.\payloads\impact\c0015_impact.ps1 -Manifest <impact-manifest.json> -Action Run

.\payloads\impact\c0015_impact.ps1 -Manifest <impact-manifest.json> -Action Rollback
.\payloads\impact\c0015_impact.ps1 -Manifest <impact-manifest.json> -Action Verify
```
